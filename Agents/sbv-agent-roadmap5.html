01 — Orientation

How this actually works

The short version, no jargon.

Think of it as an assembly line with seven stations. A folder of the client's documents goes in one end. A drafted valuation report comes out the other. Each station does exactly one job, hands its work to the next, and writes down anything it couldn't figure out.

One job each

Every agent produces one thing — a worksheet, a memo, a number, a report. Not "handles the financials." One noun.

That's deliberate. An agent with one job either does it or visibly doesn't. An agent with four jobs fails at one of them quietly.

They never decide

No agent picks a multiple, chooses a weighting, or concludes what a business is worth. Those arrive from Nancy on an input sheet, and the agent applies them.

If an agent doesn't have a number it needs, it stops and says so. It does not estimate, default, or guess.

They flag, they don't fix

When something's wrong in the source documents — a mislabeled file, a total that doesn't add up — the agent reports it and keeps going. It never quietly corrects a number.

Everything it flags lands in one file per client, so nothing gets lost between stations.

What Nancy actually does to run it. Drop the client's documents into that client's Inputs folder. Tell the first agent the business name. It asks a handful of questions with clickable answers — no typing paragraphs — and sets up the folders. Then run the agents in numbered order. Each one finishes by showing her what it made, telling her what needs her eyes, and asking whether to continue.

03 — The team

What each agent needs, and what it gives back

Every card links to that agent's real output from the Project Firefly test run — for red pen.

Station 01

Intake

Sets the engagement up, reads every source document before anything else touches them, and opens the flags file the whole team writes to. The only agent that knows the client's real name.

Built · run for real · standing context reconfirmed
What it needs from you
  • Which tier — Express or Explore
  • SDE, EBITDA, or both
  • The client's documents in the Inputs folder
What you get back
  • A codename, suggested from what the business does
  • The valuation date, proposed from the most recent statement and confirmed with you rather than asked as an open question
  • The folder structure, ready for every other agent
  • A one-page setup file every later agent reads first
  • A flags file, if it found problems — stated as fact, never offered as a question you have to opt into hearing
It no longer asks for the business name. That's on the financials, so it reads it there instead. And it asks with buttons, not blanks — tier, earnings basis, codename all arrive as clickable options.
On Firefly it caught
  • A file named Payroll2025.pdf whose contents actually cover January–July 2026. It read it as 2026 data and said so — it did not rename the file or reassign the year.
  • Payroll2026.pdf has pages but no readable text — a scan. Skipped and flagged.
  • A 2026 partial year present in the documents, excluded automatically — no partial period reaches the recast now regardless of instruction.
  • On the August 31 re-run, standing context was checked against the source documents a second time and nothing had changed — confirmation the fix held, not just a fresh guess.
Where its findings go — the flags file

Intake creates one flags page per client, and every later station adds to it. It's the single place to look to see what needs a person before the numbers can be trusted — so it lives here, with the agent that starts it.

  • Two levels only — Needs an answer (don't trust the output yet) and Worth a look (output stands, but look at this)
  • Renamed from developer shorthand — Gary had to ask what the old terms meant on the call, and if Amanda would too, they'd failed
  • Each station adds its own section; nobody overwrites anybody
  • Every item is something a person can actually resolve
Flags are not observations. "Gross margin held healthy" is an observation and belongs in the memo. "No add-backs file was supplied" is a flag. Your distinction from the call, now enforced.

Station 02

Recast Worksheet

Takes the client's P&L exactly as their bookkeeper wrote it, adds back what a buyer wouldn't inherit, and produces normalized earnings. The foundation everything else stands on.

Rebuilt against your read-through · run for real on August 31 · verified
What it needs from you
  • Profit & loss statements only — two years minimum, three preferred. Nothing else in the client's folder gets opened here anymore, which is most of the slowdown people noticed.
  • Twelve full months per statement, or nothing — a partial year stops the run rather than getting processed with a label
  • An add-backs file, if you have one
  • Replacement compensation for the departing owner, for the EBITDA Adjustment
  • Tax returns, if you want them cross-checked
What you get back
  • One worksheet per year — statement, add-backs, adjusted, notes
  • A multi-year comparison with percentages
  • A summary page with SDE and EBITDA only — no weighting, no EBIT
  • All five as printable pages, plus spreadsheets
Account names are still the client's own words, verbatim — that hasn't changed. What has: two accounts sharing one name, with nothing in the books to say they're different, now combine into a single row instead of staying apart by ledger code, and the report says so in its own words so you can explain it live. Anything under $1,000 in every year still rolls into "All Other Expenses."
Caveats on Firefly, current as of August 31
  • No add-backs file was supplied. Officer's compensation and discretionary spending aren't normalized, so SDE is understated and the value range will move up once you send the add-backs.
  • Replacement compensation wasn't supplied, so the EBITDA Adjustment lines are blank on every year rather than filled with a guess.
  • Two same-named accounts in the client's books are now combined per your instruction, with both original ledger codes named in the report's own notes column.
  • This is the second full run on this engagement. The first was audited, found to be materially understated, corrected by hand as a stopgap, and is now superseded — this run reproduces the corrected figures from the agents themselves, not a hand rebuild.

Reads the multi-year comparison and says what it means — six observations, each a plain statement followed by two to four bullets.

Built · run · corrected

What you get back

05 — Boundaries

What the agents will not do

Not limitations to fix later. Design decisions.

Judgment
Choosing the multiple and the weighting
These are the two inputs that most determine the answer, and both come from Nancy. An agent that could pick them could produce a valuation, and then nobody could say whose opinion it was.
Accountability
The signature
Every output is a draft until a person reviews the flags file and signs. Nothing leaves the machine on the agents' say-so. The Certified tier is out of scope entirely — the CVA credential is the whole product there.
The conversation
Walking a client through it
The reports exist so Gary can sit next to an owner and take them through the process. The agents build the artifact. They don't do the meeting, and the artifact is only as good as that meeting is easy.
One structural safeguard worth naming. When an agent doesn't know something, it stops and asks rather than filling the gap. That's why the Firefly package has blank EBITDA rows and a preliminary range instead of a confident-looking number nobody chose. A visible gap is recoverable. A plausible invention that reaches a client is not.
