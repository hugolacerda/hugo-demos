Part 01  /  How To Run One
Two Steps
It’s as hard as it needs to be

Two steps to run any agent.

No setup. No prompt to write. No context to paste. You open one file, you say one sentence, and the agent does the rest.

Step 01
Open the start-here file.
In the agent’s folder, open 01-start-here.html. That’s the only file you ever open to run an agent — the front door. Cowork picks up the folder as your working context.
Step 02
Say “Let’s run this agent.”
Five words. The agent reads its own start-here, golden example, process, context, and quality — in that order — then goes to work.

That’s the whole interface. Everything else — the five-file traversal, the questions it asks, the quality gates — happens because you opened the right file and said the right sentence.

The 3-3-3 Method
Part 02

The 3-3-3 Method.

A second agent. Point it at any artifact — including the agent you just ran — and it produces nine targeted improvements in three rounds of three. With an advisor, a rubric, and a snapshot at the end of every round.

Iteration beats one-shot. Action produces information.

Part 02  /  Principle
Why Three Rounds
The principle

One pass at nine ideas
is worse than three passes at three.

One Big Pass
  • You guess at nine improvements before the artifact has changed.
  • Half of them turn out to be the wrong call once the surface moves.
  • You can’t see which idea actually moved the rubric.
  • Output is hard to diff. Hard to learn from.
Three Rounds Of Three
  • Round 1 changes the surface and reveals what to fix in Round 2.
  • Round 2 deepens what Round 1 surfaced.
  • Round 3 polishes and harmonizes what’s left.
  • Every round is a snapshot. The artifact teaches you what to do next.

Why Three Rounds
Part 02  /  Structure
Three Inputs
The structure

An advisor. A rubric.
Three rounds of three.

Without an advisor, “better” is the agent’s taste. With one, it’s a methodology. The advisor IS the rubric.

Step 01
Pick the advisor.
The agent proposes three candidates matched to the artifact type — landing page, dashboard, training doc, strategy memo. You pick one. Peep Laja for conversion. Tufte for data viz. Minto for memos.
Step 02
Derive the rubric.
Four to six scorable criteria pulled straight from the advisor’s published methodology. Stays stable across all three rounds — honest movement, not moving goalposts.
Step 03
Run the loop.
Three rounds. Three improvements per round. Re-read the artifact between each round — never work from a stale mental model. Score, snapshot, append to the log. Repeat.

Part 02  /  The Trigger
One Line
The 3-3-3 trigger

Point the method at any HTML file.

No setup. No context dump. The agent reads its own start-here, golden example, and process before doing anything — then runs the eleven steps autonomously. ~23 minutes from advisor pick to v3.

Prompt · 3-3-3 Method · ~23 min 
Read the 3-3-3-method agent and apply it to [path-to-your-file.html].
What you do
Pick the advisor. Confirm the rubric.
The agent proposes three candidates and derives a rubric from the one you pick. You confirm the criteria read right — or adjust before it starts. ~3 minutes of your time.
What it does
Three rounds, autonomously.
Default mode runs all three rounds without mid-flight check-ins. You walk away. You come back to v3, an improvement log, and the matrix that shows exactly where each round lifted the score.

Part 03  /  The Output
Four Sections
What it produces

A single wrap-up.html
in your project folder.

Trigger phrase: “Run project wrap-up.” The agent scans the project folder, builds the report, and saves it next to the work.

Section 01
Embedded invoice.
Before/after cost. Traditional cost of producing the same scope by hand vs. your actual investment with agents. Numbers, not adjectives.
Section 02
Improvements catalog.
Every system change made during the project. New agents, edited rubrics, updated context files, new house-style rules. The receipts of the work.
Section 03
Suggested next improvements.
Forward-looking. Patterns the agent observed across the project that didn’t make it into v1 but should land in v2. The seed of the next sprint.
Section 04
Workflow packaging + inventory.
If a repeatable workflow emerged, it gets packaged as a new agent or template. Plus a complete inventory of every file created or modified during the project.

Part 03  /  The Loop
Wrap-Up Feeds The Next Run
The closed loop

The wrap-up isn’t a report.
It’s the next sprint’s input.

01
Run an agent. The deliverable lands. You move the card from Doing to Done.
02
Apply 3-3-3 if the artifact warrants it. The improvement log captures what changed and why — one row per improvement.
03
Run the wrap-up at end-of-project. It pulls every improvement, every new agent, every system change into one catalog.
04
The catalog lands in your continuous-improvement file. Tier 1 improvements auto-apply. Tier 2 wait for one-line approval. Tier 3 wait for a conversation.
05
The next agent you run is better than the last one — not because you remembered, but because the system did.

Homework
Before our next session

Your homework.

Three tasks. They follow the same arc as today — run, improve, wrap up.

Task 01
Run an agent end-to-end.
Pick one card from your Doing column. Run the agent. Answer its questions in full sentences. Move the card to Done. This is Run 01 — expect it to ask a lot.
Task 02
Apply 3-3-3 to it.
Point the 3-3-3 method at the deliverable you just produced — or at the agent’s own start-here file. Pick the advisor from the three the agent proposes. Let it run. Bring v3 and the improvement log to next session.
Task 03
Run the project wrap-up.
On any one project — this sprint, a client, a personal one. Trigger phrase: “Run project wrap-up.” Save wrap-up.html in the project folder. Skim the suggested-next list before next session.
