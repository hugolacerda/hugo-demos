Part 01  /  The Problem
Five Failure Modes
Without an OS

Five things that go wrong
by Tuesday afternoon.

Failure 01
Stray files everywhere.
Agents save deliverables to the desktop, the workspace root, an outputs scratch folder. Two weeks later you can’t find what you shipped to whom.
Failure 02
Duplicate agents.
You build the same proposal generator three times because you can’t remember if one already exists — and there’s no registry to check.
Failure 03
No standing rules.
Every session re-explains the brand voice, the house style, the goals. The agent is smart in the moment and forgetful by morning.
Failure 04
Drift.
Work starts on a sales pitch and ends on a logo redesign. No one named the goal at the open, so nothing flagged the detour.
Failure 05
No compounding.
Every project starts from a blank page. The lessons from the last one live in your head, the chat history, or nowhere at all.
Result
A pile, not a system.
Fifty agents that don’t know about each other. The work feels heroic on Monday and impossible on Friday.

Part 01  /  The Metaphor
Why “Chief Of Staff”
The role, not the title

A real Chief of Staff
does four things.

The file at 0. Chief of Staff/chief-of-staff.html does the same four things, every session, before any other work begins.

Role 01
Names the goal first.
Before any task, the CoS asks: which monthly goal does this serve? No work begins until the goal is named. Drift gets surfaced the moment it starts.
Role 02
Holds the standing rules.
House style. File-naming conventions. Where things save. The four pre-flight rules. Everything that should be true on every project, every time.
Role 03
Delegates to the VPs.
Strategy questions go to the Strategy VP. Marketing work to the Marketing VP. The CoS doesn’t do everything — it routes.
Role 04
Knows where everything is.
The agent registry. The folder spine. The canonical sources. Every file, every agent, every standing brief — one place.

Read at session start. That’s the whole system. The CoS file isn’t a doc you reference — it’s the briefing every agent reads before it works.

Part 01  /  The Pre-Flight
Four Non-Negotiables
Section 00 of the CoS file

Four rules that override
every one-off instruction.

If a prompt asks you to break one, you ignore that part of the prompt, do the right thing anyway, and surface the override in your reply. They sit at the top of the file because they’re the floor.

A
Name the goal first.
No work begins until the monthly goal is named. Fill the bootcamp. Launch the peer group. Or explicitly outside both. Without a named goal, every session is a guess about whether this is an experiment or a craft session.
B
No stray files.
Every deliverable lives at [N. Functional Area]/4. Projects/[project-folder]/[file].html. Never loose at the root. Never invent a new top-level folder. If unsure, propose the path and confirm.
C
State the full path before any link.
Plain text first: File saved to: [folder]/[subfolder]/[filename.ext]. Then the link. The audit trail beats the convenience every time.
D
All HTML matches the house style.
Read 0. Chief of Staff/house-style.html before authoring. Don’t pattern-match off nearby files. One canonical source. One look.

Sections At A Glance
One file. Nine sections.

The whole company
in one briefing.

The CoS file is the playbook. Mission, brand, monthly goals, operating rules, canonical sources, triggered commands, the agent registry, the VP roster, and the folder spine — in that order.

Read at session start. Re-read when stuck. It is not a doc you cite — it’s the briefing the agent absorbs before it does anything else.

  • Versioned in plain sight. v1, v2, v3 sit next to each other so you can see what was true when.
  • Every agent reads it. Not every agent reads all of it — but every agent reads the parts that point at its job.

Part 02  /  How It Flows
One Task, End-To-End
A walk-through

Where a single piece
of work actually lands.

Take one request: “Build me a deck for the Tuesday client meeting.” Here’s how the OS routes it.

01
CoS reads first. Pre-flight rule A fires: which monthly goal does a Tuesday deck serve? Goal named, drift risk contained.
02
CoS routes to Sales VP. Decks for client meetings live in Sales. The CoS doesn’t build the deck — it picks the right VP.
03
Sales VP picks the agent. Looks at 4. Sales/3. Agents/, finds mastermind-pitch-deck/ — closest match, ready to run.
04
Agent runs against the right context. House style from 0. Chief of Staff/. Brand from §02. Five-file structure from Agent Builder. Output saves to 4. Sales/4. Projects/[client]/[date]-deck.html.
05
Wrap-up closes the loop. Cost logged. Improvements catalogued. Next-time suggestions queued. The system is one project smarter.

Notice what didn’t happen. No one decided where to save the file. No one re-explained the brand. No one rebuilt the deck-making prompt. The OS handled all of it.

Five minutes. Three answers. One HTML file out the other side.

Prompt · Sprint Wrap-Up · ~5 min 
You’re wrapping up Katie Milton Jordan’s Agent Builder Sprint with me. Five minutes. Three answers. One HTML file out the other side. Tone: warm, peer-to-peer. One gentle push per vague answer, then move on.

Step 1 — Find what I built.
Search my workspace. Check any `Agents/` subfolder under each numbered area, plus this sprint’s project folder. List every agent I built or worked on this sprint — name + one line each. Then ask my first name (you’ll need it for the filename).

Step 2 — Which one am I proudest of?
Show me the list. Ask: “Which one are you most proud of?”

Step 3 — Why?
Ask: “What makes that one stand out for you?” If I give a one-liner, push once — was something hard about building it, or does it now do something nothing did before?

Step 4 — How was this different?
Ask: “How was this training different from other AI training you’ve done?” If my answer is generic, push once: “Most AI training is watching someone else do it. What did you actually build this week that you wouldn’t have built otherwise?” That’s the answer we want — the hands-on part. Don’t fish more than once.

When the three answers are in, write `sprint-wrap-{firstname}.html`.

Style: Inter typography, accent #d8481f, paper #ffffff, wash #f5f4f0, ink #0a0a0a. Thin sig-line on top. Header: first name + “Agent Builder Sprint · Wrap-Up”. Three sections stacked, alternating white/wash:

  01 / WHAT I BUILT — agent list, name + one-liner each.
  02 / THE ONE I’M PROUDEST OF — name as h2, my reasoning as body.
  03 / WHAT WAS DIFFERENT — my answer, in my words.

Footer: “Agent Builder Sprint · Wrap-Up · {date}” with an accent dot.

Tell me one line: “Done. Drop the file in the Basecamp wrap-up folder.” Stop there.
