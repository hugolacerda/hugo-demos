Rubric · Agent Architecture

Five dimensions of agent instruction quality

These are the criteria the artifact is scored against at v0, R1, R2, and R3 Final. Same rubric every round — honest movement, not moving goalposts. Derived from first principles of agent design: an instruction document succeeds when the agent can execute it without ambiguity, recover from edge cases without human rescue, and produce consistent outputs across diverse inputs.

01 · Instruction Precision
Can the agent unambiguously follow every step?

No room for interpretation drift. Every verb has one meaning. Every reference points to exactly one thing. "Surgical edits" is vague; "find-and-replace on specific selectors" is precise.

02 · Failure Mode Coverage
Are the known failure modes anticipated with explicit guardrails?

What happens when the advisor doesn't exist? When the artifact type isn't in the table? When a round produces no meaningful improvement? Every fork needs a path.

03 · Information Architecture
Does the document structure match the agent's reading order?

An agent reads top-to-bottom. If a prerequisite appears after the step that needs it, the agent will skip it. Critical information must appear before the first point of use.

04 · Human-Agent Boundary
Are handoff points between human and agent explicit?

Zone 1/2/3 boundaries must specify the interaction pattern — does the agent pause and wait, present options, or proceed with a default? "You confirm" is incomplete without "here's how."

05 · Generality
Do the instructions work across the full range of inputs?

Language tied to one artifact type (dashboards, slide decks) causes the agent to pattern-match on that type. Instructions should be artifact-agnostic unless a specific callout is needed.

Round 1 · Establish

Fix reading order, close the advisor lookup gap, add the first missing fallback

An agent builder's first pass always addresses the same question: will the agent even read the right things in the right order before it starts working? Round 1 is structural.

Improvement 1 · Information Architecture
Move the preflight block above execution instructions

The preflight ("Read all three files before any work begins") was buried below the file manifest, the time budget table, and the copy-paste prompt. An agent reading top-to-bottom hits the prompt — "Read the 3-3-3-method agent and apply it to [path]" — and starts executing before it ever reaches the preflight. Moved the entire preflight block to immediately after the manifest table, before the file listing.

Improvement 2 · Instruction Precision
Add an explicit cross-reference from Step 0 to the advisor lookup table

Step 0 says "Propose 3 candidate advisors based on artifact type" but doesn't say where to find the candidates. The advisor-by-artifact-type table lives in Part B under "The right advisor depends on the work" — a human finds it by scanning; an agent may not. Added a direct pointer: "Consult the advisor table in Part B § The right advisor depends on the work."

Improvement 3 · Failure Mode Coverage
Add a fallback path when the artifact type isn't in the advisor table

The advisor table covers five artifact types (landing page, design/UX, dashboard, training doc, strategy memo). An agent given an API reference doc, an email template, or a CLI help page has no guidance. Added a fallback row and an explicit instruction: "If the artifact doesn't match a row, describe it in one sentence and propose 3 advisors from the closest matching row. State which row you adapted from and why."

Round 2 · Deepen

Specify interaction patterns, define "surgical," and generalize dashboard language

With reading order fixed and the first fallback added, Round 2 targets the instructions an agent will actually execute: what does "confirm" mean in practice? What counts as a surgical edit? And why does an anti-degradation protocol reference a JavaScript function that most artifacts won't have?

Improvement 4 · Human-Agent Boundary
Specify the interaction pattern for advisor selection

Zone 2 says "The agent drafts, you confirm" but never defines the mechanic. Does the agent pause? Present a numbered list? Proceed with a default after 30 seconds? An agent without an explicit pattern will either barrel through without asking or present options inconsistently each time. Added: "Present the 3 candidates in a numbered list. State which one you'd pick as default and why. Wait for the human to confirm or override before continuing to Step 1."

Improvement 5 · Instruction Precision
Replace "surgical edits only" with a concrete definition

"Surgical edits only — never rewrite" is the right principle but an incomplete instruction. An agent interprets "surgical" differently depending on its training data. One might consider replacing three paragraphs to be surgical; another might refuse to change more than one line. Replaced with: "Use targeted find-and-replace on specific elements, selectors, or text blocks. Each edit must map to exactly one improvement. Never regenerate the entire file from scratch."

Improvement 6 · Generality
Generalize Protocol 04 from dashboard-specific to artifact-agnostic

Protocol 04 reads: "verify new functions are called from updateAllCharts() or the equivalent master function." This is dashboard-specific language. An agent improving a training document, a process file, or a strategy memo will either skip this protocol entirely (no charts) or try to find a JavaScript function that doesn't exist. Generalized to: "Verify every new element is reachable — called from a master function, linked from navigation, or visible in the document flow. Orphaned code and orphaned content are both dead."

Round 3 · Polish

Resolve scope ambiguity, add the stall-out fallback, relocate the taxonomy

Round 3 cleans up the remaining issues that Rounds 1 and 2 surfaced: a scope statement that contradicts the preflight, no path for when a round produces diminishing returns, and a classification sidebar that interrupts execution training.

Improvement 7 · Generality
Make the scope statement explicit about internal vs. customer-facing artifacts

The hero says "Works on dashboards, training documents, marketing pages, reports — any HTML file." But Preflight 03 says internal files must use the house style while customer-facing files use a brand style. Can the agent improve a customer-facing page? Yes — but the improvement log it writes about the run is internal and must use house style. This distinction was implicit. Made it explicit: "The target artifact can be any HTML file — internal or customer-facing. The run folder and improvement log are always internal documents in the house style."

Improvement 8 · Failure Mode Coverage
Add a diminishing-returns protocol for late rounds

No guidance for when Round 2 or Round 3 can't find three meaningful improvements. An agent will invent marginal changes to fill the quota — exactly the "miniature font tweaks" failure mode. Added Protocol 06: "If a round cannot identify 3 improvements that each move a rubric dimension by at least 0.5, stop at fewer. Log why the remaining slots are empty. Two strong improvements beat three filler changes."

Improvement 9 · Information Architecture
Relocate the agent-levels taxonomy out of the execution training

The "Level 4 classification" section and seven-row agent-levels table sit in the middle of Part B, between the anti-degradation protocols and Part C. An agent reading Part B to understand how to execute the method hits a taxonomy sidebar that doesn't affect execution. It's useful reference but it interrupts flow. Moved to a standalone callout at the end of Part B with an explicit note: "This classification is for reference. It does not affect how the agent executes the 3-3-3 method."
