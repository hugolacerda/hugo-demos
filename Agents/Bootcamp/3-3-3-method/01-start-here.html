The 3-3-3 Method

A rubric-first, eleven-step method: define what better means, then improve any HTML document through three rounds of three targeted improvements. Nine enhancements, four per-round snapshots, one improvement log. Works on dashboards, training documents, marketing pages, reports — any HTML file.

Part A · Manifest

What this agent produces, what it needs, and how long it takes.

What this agent produces

Input: any HTML file — dashboard, training doc, marketing page, tool, report — plus an advisor whose methodology defines the rubric (Peep Laja for CRO, Oliver Reichenstein for typography, April Dunford for positioning).

Output: a self-contained run folder. The source file is never edited directly. The improvement log is the primary deliverable — the improved HTML is its byproduct.

The agent proposes 3 candidate advisors based on the artifact type and asks the human to choose before starting.

Estimated time

The full loop is designed to run in one sitting. Default mode: the agent runs all three rounds without mid-flight check-ins, and you review at the end.

Per-round snapshots let you diff v1 against v2 against v3 to see the method's progression — not just the endpoint.

Before You Run · Mandatory Preflight

This file is not self-contained. Do not treat it as such. Step 0 has substeps that appear only in 03-process.html. Reading only this start-here file is the #1 observed failure mode for this agent.

Preflight 01
Read all three: 01, 02, and 03 — before any work begins.

You must read 01-start-here.html, 02-golden-example.html, and 03-process.html in full before executing Step 0. The full Step 0 substeps (library check, advisor-file creation, run folder scaffolding) live in the process file. Skipping any of these three files is a protocol violation.

Preflight 02
Check the advisor library before scoring anything.

After the user picks the advisor, look in the domain Advisors/ folder (3. Marketing/2. Advisors/ for marketing work, 4. Sales/Advisors/ for sales work, and so on). If the advisor file exists, read it and derive the rubric from it. If it does not exist, create the advisor file before continuing — match the format of the existing files in that folder. The rubric you're about to use should live in the library, not just in this one run's log.

Preflight 03
Read the house style before writing any internal HTML.

Before creating the run folder, the advisor file, the improvement log, or any per-round snapshot, read 0. Chief of Staff/house-style.html and copy its <style> block verbatim into every new internal file you create during this run. Do not pattern-match off the target artifact (the target may be customer-facing marketing work in a brand style — that's fine for the artifact itself, but anything you write about the run — advisor files, improvement logs, round snapshots as index pages, quality notes — is internal and must use the house style). Per Chief of Staff Rule 13.

Preflight 04
State the preflight out loud before Step 0.

Before running Step 0, state in plain text: (a) which three agent files you've read (01, 02, 03), (b) whether the advisor file exists in the library — and if not, that you're about to create it, and (c) that you've read house-style.html and will use it for all internal files in this run. This is a forcing function — if you can't say it, you haven't done it.

Part B · Agent Training

What the agent does at each step and why. Read this to understand what's happening under the hood — or skip to Part C for your role.

Core principle: action produces information

Iterating in three rounds of three improvements produces dramatically better results than one-shotting nine improvements at once. Each round's implementation reveals new opportunities that weren't visible before. The artifact itself teaches you what to improve next.

Three rounds. Round 1 improvements change the surface area of the artifact, revealing new opportunities. Round 2 deepens what R1 uncovered. Round 3 polishes and harmonizes.

Three per round. Not five or ten. Three keeps each round implementable in a single coherent pass without losing track of interconnections. Small enough to track precisely. Large enough to matter.

Advisor → rubric

Before the rubric, pick the advisor. The advisor IS the rubric. Without one, "better" is the agent's taste.

  • Step 0 · Select: Propose 3 candidates matched to the artifact type.
  • Step 1 · Derive: 4–6 scorable criteria from the advisor's published methodology.
  • Stays stable: Same rubric across all three rounds — honest movement, not moving goalposts.

The right advisor depends on the work

A landing page needs different eyes than a training document. The agent proposes three candidates based on the artifact type and asks the human to pick — or the human names their own.

The execution loop

Two setup steps, then three rounds of three. Each round ends with a rescore and a logged section in improvement-log.html.

Setup
Step 0
Select advisor + check library + create run folder

Propose 3 candidate advisors based on artifact type. Human picks one. Check the domain Advisors/ folder (e.g. 3. Marketing/2. Advisors/) for an existing file on that advisor. If it does not exist, create the advisor file before continuing — matching the format of other files in that folder, containing the 4–6 rubric dimensions, core mental models, signature moves, and common mistakes. Then create runs/{NN}-{advisor-slug}/ and copy the input file in as v0-baseline.html. Full substeps in 03-process.html — do not skip.

Step 1
Load advisor's rubric

Derive the 4–6 criterion rubric from the chosen advisor's published methodology. Score the baseline against each criterion before any improvements are suggested.

Round 1 — Establish
Step 2
Analyze & suggest

Read the artifact against the rubric. Identify 3 high-impact improvements: surface changes that will reveal deeper opportunities.

Step 3
Implement + save v1

Copy v0-baseline.html to v1.html. Apply the 3 improvements to v1.html. Surgical edits only — never rewrite. v0 stays untouched.

Step 4
Rescore + log Round 1

Rescore v1 against the rubric. Write Round 1 into improvement-log.html: 3 improvement cards plus the R1 column in the scoring matrix.

Round 2 — Deepen
Step 5
Re-read v1 + suggest

Re-read v1.html directly — not from memory. Suggest 3 more improvements informed by what Round 1 revealed.

Step 6
Implement + save v2

Copy v1.html to v2.html. Apply the 3 improvements. Verify integration with Round 1 edits. v1 stays frozen.

Step 7
Rescore + log Round 2

Rescore v2 against the rubric. Append 3 improvement cards to improvement-log.html and add the R2 column to the matrix.

Round 3 — Polish
Step 8
Re-read v2 + suggest

Re-read v2.html. 3 final improvements focused on polish, coherence, and the highest remaining rubric gaps.

Step 9
Implement + save v3

Copy v2.html to v3.html. Apply the 3 final improvements. Ensure all 9 improvements work together. v2 stays frozen.

Step 10
Finalize log + narrative

Rescore v3. Add R3 and Δ columns to the matrix. Write the closing narrative: where the biggest lifts landed, which dimensions moved most, and why.

Five protocols — anti-degradation

Rules that prevent the agent from introducing bugs or losing functionality while improving.

Protocol 01
Define the rubric before suggesting

Before Step 2, define what "better" means. Specific enough to guide suggestions, stable enough to judge all three rounds consistently.

Protocol 02
Re-read before each round

Before implementing, re-read the current state of the file. Do not rely on a stale mental model. The artifact has changed since the previous round.

Protocol 03
Targeted edits only

Never rewrite the entire file. Use surgical, precise edits. This preserves existing functionality and makes changes traceable.

Protocol 04
Test integration points

After each round, verify new functions are called from updateAllCharts() or the equivalent master function. Orphaned code is dead code.

Protocol 05
Improvement-log fidelity

The log must document each improvement's label, title, rationale; before/after code grid; rubric scores per round (v0→v1→v2→v3→Δ); and a closing summary narrative explaining where the lifts landed and why. No vague summaries.

Level 4 classification

The 3-3-3 Method is a Level 4 Agent: five primitives, sequential execution with a feedback loop, scoped to quality iteration on a single artifact.

The 5 primitives: Read (analyze), Suggest (propose improvements), Implement (edit snapshot), Document (append to log), Loop (feedback across rounds).

Part C · Your Role

What the agent handles, what it assumes, and where you come in.

The three zones

Every part of this agent's work falls into one of three zones. Understanding which is which tells you where the agent stops and you start. Think of the agent as a skilled developer you just hired — some things they can do on their own, some they'll take a reasonable swing at, and some they need to hear from you first because the answer is about your intent, not the code.

Zone 1 · 60%
The agent handles it

The method itself runs autonomously.

  • The 11-step execution loop: Advisor selection + 3 rounds × 3 improvements × documentation. Fully autonomous.
  • Run folder + per-round snapshots: Creates runs/{NN}-{advisor-slug}/ with v0-baseline through v3, editing only snapshots — never the source.
  • Re-reading before each round: Built into the protocol. Never works from a stale model.
  • Surgical edits that preserve function: Anti-degradation protocols prevent breaking existing features.
  • The improvement log: Rubric card, scoring matrix (v0→v1→v2→v3→Δ), 9 before/after cards, closing narrative.
  • Integration testing: Verifying new code actually connects to the master orchestration function.
  • Rubric scoring across rounds: Consistent scoring from the rubric defined in Step 1.
Zone 2 · 25%
The agent drafts, you confirm

Judgment calls where the agent takes a swing.

  • The advisor: Agent proposes 3 candidates matched to the artifact type. You pick — or name your own.
  • The rubric itself: Derived from the chosen advisor's published methodology. You confirm the criteria read right — or adjust before it starts.
  • Which 3 improvements per round: The agent picks what it thinks matters most against the rubric. Usually correct, but your priorities might differ.
  • Round 1 strategy: The agent chooses "surface changes that reveal deeper opportunities." It may not know which surfaces matter most to you.
  • Design and UX decisions: Color, layout, interaction patterns. The agent follows the golden example, but your brand or audience may differ.
Zone 3 · 15%
You create this

Intent the code can't reveal.

  • The input artifact: The agent needs an HTML file to improve. You provide it.
  • Business context: "This dashboard is for executives who only have 30 seconds" or "the main user is colorblind" — intent that isn't visible in the file itself.
  • Priority overrides: If you know which dimension matters most ("performance over aesthetics" or "mobile-first"), tell the agent before it starts.
  • Acceptance of the final output: Only you can say "this is done." The agent scores against the rubric, but the rubric is a proxy for your judgment.

Your two jobs

Job 1 — Confirm. Pick the advisor from the agent's 3 candidates (Step 0). Review the rubric derived from their methodology (Step 1). Scan the improvement log after each round. Say yes, or redirect.

Job 2 — Create. Provide the input artifact. Share any business context the code can't reveal. Set priority overrides if the default rubric weighting doesn't match your needs. Accept the final output.

That's it. The agent runs the method. You steer and accept.

Job checklist

  • Pick the advisor from 3 candidates
  • Review the derived rubric before it starts
  • Scan the improvement log at the end
  • Provide the input artifact
  • Share business context the code can't reveal
  • Set priority overrides if needed
  • Accept the final output

Why this agent is 60 / 25 / 15

The 3-3-3 Method is more autonomous than a content agent because the method itself is the value. The structure — three rounds, three per round, rubric-first, per-round snapshots, improvement log — is fixed. It doesn't change based on the input. That's a lot of Zone 1.

Why Zone 2 is thin

The rubric and improvement selection are judgment calls, but the agent makes reasonable ones by reading the artifact against known quality patterns. Most of the time, the human confirms rather than overrides.

Why Zone 3 is thinner

Zone 3 is small because the human's job is mostly about intent — what the artifact is for, who uses it, and what "done" means. Once that's provided, the agent takes it from there.

Shrink your job further

If you include a brief artifact brief with your input — audience, purpose, top 2 priorities — the rubric moves from Zone 2 to Zone 1. The agent will nail it on the first try.
