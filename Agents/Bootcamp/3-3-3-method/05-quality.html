Production System · Quality

The 3-3-3 Method
— Quality

Gates, scoring rubric, and the verification checklist that decides whether a run is production-quality. All nine gates must pass, and the weighted rubric must score at least 80/100.

Section 1 · Gate Checks

Nine pass/fail gates.

All gates must pass. Failure on any gate blocks progression. Gates run at specific moments across the 11-step loop — before, during, and after each round.

Two Rubrics in Play

Step 1 creates a project-specific success rubric for the artifact being improved. This file contains the production-quality rubric for whether the agent executed the 3-3-3 method well. Both matter.

Section 2 · Weighted Rubric

Scored out of 100 points.

Three bands — Implementation, Documentation, Method Adherence — totaling 100 points. Pass threshold is 80/100.

Band 1 · Implementation
Implementation Quality — 40 points max · Q1–Q4.
Band 2 · Documentation
Documentation Quality — 30 points max · Q5–Q8.
Band 3 · Adherence
Method Adherence — 30 points max · Q9–Q11.

Implementation Quality · 40 pts.

ID Check Pts Criteria
Q1Feature Depth15Each improvement is substantive, not cosmetic. 15=all 3 add real analytical or navigational capability. 10=2 substantive, 1 minor. 5=mostly cosmetic. 0=no real value added.
Q2Code Integration10New features are properly wired into existing architecture. 10=all use existing data structures, respect filter state, integrate with master update. 5=some features work independently of filters. 0=disconnected islands.
Q3Cross-Component Linking10Features connect to each other and to existing components. 10=multiple click-through paths between components. 5=some linking. 0=all features siloed.
Q4Error Handling5Features handle empty data, missing values, edge cases. 5=graceful degradation. 3=mostly handles edges. 0=breaks on empty data.

Documentation Quality · 30 pts.

ID Check Pts Criteria
Q5Comparison Specificity10Before/after descriptions are concrete (function names, line counts, specific behaviors). 10=precise and verifiable. 5=somewhat vague. 0=generic hand-waving.
Q6Impact Articulation10Each improvement's Impact statement explains user-facing value in terms of what decision or action the user can now take. 10=actionable insights. 5=theoretical benefits. 0=no impact statements.
Q7Cumulative Narrative10The closing summary includes a coherent narrative of the full transformation arc and the final advisor-rubric scoring matrix (v0→v3→Δ). 10=tells the story of where lifts landed and why, matching the golden example. 5=lists stats only. 0=missing.
Q8Teach-Through-The-Framework Memo10After the Summary Block, the log includes a teaching memo restating the advisor's mental model, giving a "what to spot next time" bullet for each of the 9 improvements (pattern + cue + corrective move), and closing with a 3–5 item self-review checklist. The user should leave knowing how the advisor sees the world. 10=full memo. 5=partial. 0=missing.

Method Adherence · 30 pts.

ID Check Pts Criteria
Q9Round Distinctiveness10Each round has a distinct character (Round 1=foundation, Round 2=deepening, Round 3=polish). 10=clear progression in sophistication. 5=some overlap. 0=all rounds suggest similar improvements.
Q10Informed by Previous Round10Round 2 and 3 suggestions explicitly reference what the previous round enabled or revealed. 10=clear causal chain. 5=some references. 0=rounds are independent.
Q11Category Coverage10Across all 9 improvements, at least 5 different taxonomy categories are represented. 10=6+ categories. 7=5 categories. 5=4 categories. 3=3 categories. 0=fewer than 3.

Section 3 · Per-Round Verification

Run after each round.

After Steps 3, 6, and 9 — the three implementation points — run this eight-item checklist before writing the improvement log.

Post-Implementation Checklist
Eight checks after Steps 3, 6, 9.
  • Count total lines and compare to pre-round count
  • Verify all new functions exist (grep for function names)
  • Verify master update function calls new update functions
  • Verify DOMContentLoaded block includes new event listeners
  • Verify no JavaScript syntax errors (check for unclosed braces, missing semicolons)
  • Verify new CSS doesn't conflict with existing styles
  • Verify new HTML elements have proper IDs referenced by JavaScript
  • Quick functional check: Do filters still cause all components to update?
Tip

Run this checklist immediately after implementing features and again after the improvement log is written. A quick 2-minute pass can catch integration issues before moving to the next round.

Section 4 · Scoring Guide

What the score means.

Use the rubric above to assign points. Sum all scores (Implementation + Documentation + Method Adherence). The threshold for production quality is 80/100.

Important

This 80/100 threshold judges whether the agent executed the method well. Separately, the Step 1 project rubric judges whether the artifact actually got better in the ways the user cares about. Don't conflate the two.

90–100 · Exceptional
Compelling transformation story.

All improvements are deeply integrated, cross-linked, and the improvement log tells a compelling transformation story. The artifact is dramatically more powerful. Every gate passes with high confidence. Documentation is detailed and narrative-driven.

80–89 · Strong
Solid, well-integrated, minor gaps.

Improvements are solid, well-integrated, and documented. Minor gaps in linking or coverage. All gates pass. Comparison files are clear and specific. Some features may lack cross-component relationships, but the overall arc is clear.

70–79 · Adequate
Works but disconnected or thin.

Improvements work but some feel disconnected or the documentation is thin. Most gates pass. May have minor regressions or features that don't respond to filter changes. Comparison files exist but lack detail or narrative coherence.

Below 70 · Needs Rework
Gates fail, integration issues, vague docs.

Features may be cosmetic, poorly integrated, or documentation doesn't accurately reflect changes. One or more gates fail. Integration issues prevent filters from triggering updates on new components. Comparison files are missing, inaccurate, or vague.

When a Round Scores Below 80

Do not advance to the next round. Rework the failing components, re-test the gates, and rescore. The 3-3-3 method is predicated on building strong foundations; weak rounds create cascading issues downstream.

Quick Reference

Gate and rubric acronyms.

The at-a-glance summary you'll reach for during a live run.

Gate acronyms.

G0 · Rubric + Advisor Library Gate
Before Step 2 and again in Step 10.

Ensures the project-specific rubric exists, is used throughout the run, AND that the advisor file exists in the domain Advisors/ folder. If the advisor file is missing, the agent must create it in Step 0 before deriving the rubric. This makes the methodology reusable across future runs instead of living only in this run's log.

G1–G7 · Implementation Gates
Check after each round's implementation.

Run after Steps 3, 6, and 9. All must pass before moving forward.

G8 · Progression Gate
Check after suggestion phases.

Run after Steps 5 and 8. Ensures each round builds on the previous one.

Rubric acronyms.

Q1–Q4 · 40 pts · Implementation Quality
Substantive, integrated, cross-linked, robust.

Measures whether new code is substantive, integrated, cross-linked, and robust.

Q5–Q8 · 30 pts · Documentation Quality
Detailed, impactful, teaches the framework.

Measures whether the improvement log is detailed, impactful, and tells a coherent story — including the Teach-Through-The-Framework memo.

Q9–Q11 · 30 pts · Method Adherence
Distinct, informed, and covers the taxonomy.

Measures whether each round is distinct, informed by the previous, and represents coverage of the taxonomy.

Passing Criteria

All 9 gates must pass AND quality rubric score ≥ 80/100 to advance to the next round or declare the project complete.
