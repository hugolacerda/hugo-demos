Wrap-Up Process

Machine-readable steps for documenting, invoicing, and archiving completed projects. Follow in order. Each step produces a specific deliverable that feeds the next step.

Phase 0: Orientation

Before you begin intake, study the golden example. You need to know what a complete wrap-up looks like before you start building one.

Step 0
Study the Golden Example

Read 02-golden-example.html. This is the FairPlay half-day wrap-up report. It shows the exact structure, detail level, and visual format you're aiming at.

What to internalize:
  • BLUF section — one-paragraph summary of accomplishments
  • Stats grid — session length, files created, revisions, roles
  • Improvement cards — delivered improvements, each tagged with outcome type
  • Workflow packaging table — whether work was packaged as repeatable agent
  • Full artifact inventory — every file created/modified with paths

This is your target. Every wrap-up should match this standard.

Phase 1: Intake

Confirm project details and scan the project folder. The goal is to leave this phase with a clear inventory of work completed.

Step 1
Gather Inputs

Confirm with user:

  • Project name (required) — Full name of the completed project
  • Project folder path (required) — Absolute path to the project directory
  • Client name (recommended) — Who benefited from or commissioned the work
  • Scope/deliverables (recommended) — Or plan to scan folder for deliverables list
  • User's active time (recommended) — Hours spent actively directing/reviewing

If no project folder provided: Ask before proceeding. You need the folder path.

If no active time provided: Estimate from file count and complexity. Ask: "How many hours did you actively direct or review?" If unsure, estimate 25% of total elapsed time.

Step 2
Scan the Project Folder

Read all files in the project folder. Catalog:

  • Count deliverables — how many distinct outputs
  • Note versions/iterations — how many revision rounds
  • Identify complexity — simple task or multi-step workflow
  • Note file types — HTML, documents, databases, config, code, etc.

This inventory feeds the invoice generation and artifact list.

Complexity signals: Multi-file projects, cross-functional deliverables, design systems, code with multiple modules, or projects requiring research — these are higher complexity.

Phase 2: Build Invoice Section

Calculate the before/after cost comparison. The invoice section will be embedded in the wrap-up report and is the first element the user sees.

Step 3
Build Traditional Line Items ("Before" Column)

For each role that would typically touch this project, create a line item: Role: Task @ $XXX/hr. Use the pricing guide from 04-context.html.

Common roles and rates:

  • Project Manager — $150/hr
  • UX Designer — $175/hr
  • UI Designer — $175/hr
  • Frontend Developer — $200/hr
  • Backend Developer — $200/hr
  • QA Engineer — $125/hr
  • Copywriter — $150/hr
  • Designer + Dev blended — $185/hr

Estimating hours: Look at scope and deliverables. A custom design system might be 40-80 hours. A simple template might be 2-4 hours. A content refresh might be 8-16 hours. Include ALL roles that would typically touch the project.

Step 4
Calculate the "After" Column

Compare the traditional approach to what actually happened:

  • Your time: Minutes of active direction/review converted to billable hours. Round up to nearest 0.5 hour.
  • AI costs: Always $1. This covers the computational cost.
  • Files created: Count of deliverable files produced
  • Revision rounds: "Unlimited" — the AI handled revisions without additional cost
  • Delivery: "Instant" — everything was delivered same-session

The "After" total: (User hours @ $150/hr) + $1 AI cost. The difference is the savings.

Step 5
Create the Invoice HTML Section

Create a before/after layout that will be embedded in the wrap-up report. Use a simplified inline structure with grid columns, items, totals, and a savings badge.

  • Left column ("Before"): Role-based line items, struck through, muted text
  • Right column ("After"): User's time, $1 AI, deliverables, accent highlight on totals
  • Totals row: Show traditional total vs. AI-assisted total
  • Savings badge: Highlight the dollar amount saved at the bottom

This HTML will be inserted into the wrap-up report, not saved as a separate file.

Phase 3: Documentation

Capture what changed in the operating system and what could be improved next time.

Step 6
List System Improvements

Catalog every change made to the operating system during this project:

  • New or updated context files
  • New process documentation
  • New rules or templates
  • New scoring logic or frameworks
  • Folder structure changes
  • Any new agent packages created

These are "delivered improvements" — permanent additions to the system that benefit future projects.

Step 7
Suggest Additional Improvements

Looking forward, identify patterns and opportunities:

  • Repeated manual steps → agents: Did you do the same task multiple times?
  • Patterned decisions → rules: Were there consistent decision points?
  • Research → context files: Did you look up the same information repeatedly?
  • Quality checks → checklists: What did you manually verify?
  • Outputs → templates: Did you produce similar outputs?

These are conversation starters, not a to-do list. Present them for discussion. The value is in the dialogue, not in a list of action items. Frame each suggestion with enough reasoning that the human can engage meaningfully.

Step 8
Package as Workflow (if applicable)

If the project produced a repeatable process, consider packaging it as a five-file agent.

When to package: The work is repeatable, has clear inputs/outputs, and will likely run again.

When not to package: One-off project with no repeatable pattern. Note "No workflow packaged — one-off project" and move on.

Phase 4: Delivery

Produce the wrap-up report, run quality checks, and report back to the user.

Step 9
Write the Wrap-Up Report

Create wrap-up.html in the project folder root. This is the only output file.

Required sections (in order):

  1. BLUF — One paragraph summarizing what was accomplished
  2. Embedded Invoice Section — The before/after cost comparison
  3. Session/Project Stats — Grid showing files created, active time, savings
  4. System Improvements Delivered — Cards for each system change
  5. Suggested Improvements — Cards with "suggested" tag
  6. Workflow Packaging Assessment — Table showing what was packaged
  7. Full Artifact Inventory — File table with paths for every deliverable

Use the production design system from 04-context.html for styling.

Step 10
Self-QC

Run the five quality gates from 05-quality.html against your own output.

QC requirement: Every blocker must pass. No more than two majors remaining. If you find blockers, fix them before reporting to the user.

Step 11
Summarize to User

Report back with:

  • Every file created/modified: List with full paths
  • Savings number: Highlight the cost savings from the invoice
  • Single most important improvement: What had the biggest impact
Step 12
Review Suggestions Together

Walk through the suggested improvements with the human. This is a conversation, not a handoff. Expect them to push back, debate, and pick at least one suggestion to execute right now.

When they pick a suggestion: Execute it in the same session. This bridges wrap-up to next project.

When they push back: Engage with the question. Explain your reasoning. The discussion itself is valuable.

Step 13
Update Agent Registry

Read the agent registry in 0. Chief of Staff/chief-of-staff-v3.html and make two types of updates:

  • New agents: If this session created any new agents, add them to the registry under the correct department.
  • Last run: For every agent that was used or modified, update its last-run date to today's date.

This is the closed loop. As long as every session ends with a project wrap-up, the registry stays current. The wrap-up IS the maintenance mechanism.
