The Vision

From execution machine to judgment layer

Nancy currently spends most of her time on work that is mechanical, repeatable, and document-heavy — recasting financials, formatting tables, writing narrative around numbers she already understands, building reports from scratch for every client. This is work an agent team can own.

The judgment calls are different. Professional interpretation. NACVA sign-off. The client relationship. The read on whether a number tells the real story or a misleading one. Those belong to Nancy. The goal is to hand everything else off.

This roadmap builds that handoff systematically — phase by phase, agent by agent, each one taking a discrete slice of the production work until Nancy receives a near-complete report draft and her job becomes editing and approving rather than writing from zero.

Long-term, as the agent team matures and Nancy's sign-off patterns compound into training data, the system becomes capable of producing valuations with minimal human initiation — triggered by GHL, completed by agents, reviewed by Nancy in a fraction of the current time.

End State

"Client documents arrive. The agent team processes them, recasts the financials, writes the observations, pulls the Value Builder summary, drafts the full narrative, and formats the report. Nancy opens a near-complete draft, edits what needs editing, signs off, and delivers. The grunt work is gone."

Required Infrastructure — Build Before Phase 3

The Operating System Layer

Agents without an OS have amnesia. Each session starts from zero, agents don't know each other exist, and there's no registry to tell CoWork what to run next. These four components are required infrastructure before Phase 3 orchestration is possible.

Naming Convention Fix — Action Required Now

The Recast Worksheet Agent and Observations Agent use inconsistent file naming. Recast uses 01-start-here.md with dashes. Observations uses 01_agent_instructions.md with underscores and different slot names. Pick one standard — the Recast convention is closer to Katie's format — and update the Observations Agent files before building any new agents. A chief-of-staff file that references agents by pattern cannot work with inconsistent naming.

OS — 01

Chief-of-Staff File

A single chief-of-staff.md at the root of the Agents folder. Every CoWork session opens with it. Contains: current top goals, standing rules, agent registry, folder spine, and file-naming conventions. Replaces re-explaining context every session.

OS — 02

Agent Registry

A table inside the CoS file listing every built agent: what it does, where it lives, what it receives as input, what it outputs, and when it last ran. Solves "did we already build this?" and makes the fleet visible at a glance.

OS — 03

Folder Spine

Numbered functional folders under the Agents directory so every agent has one obvious home. Minimum: 01-Foundation/, 02-Assembly/, 03-Orchestration/, 00-ChiefOfStaff/. Every deliverable file lives at a predictable path.

OS — 04

Handoff Spec

A single document defining what each agent passes to the next — exact file names, formats, and required fields. Without this, Phase 3 sequencing requires a human to manually route output. With it, agents can chain automatically.

Phase 1 — Foundation

The Analytical Core

The two agents that every downstream agent depends on. Nothing in the pipeline works until these are producing reliable output. Agent 1 handles the raw financial processing. Agent 2 turns the output into the analyst narrative Nancy would otherwise write herself.

Agent 01 Built
Recast Worksheet Agent
Raw financials in. Clean recast out.
What it does

Takes raw client financial statements — tax returns, P&L, balance sheet — and produces a normalized recast income statement. Identifies discretionary expenses, owner add-backs, and one-time items. Outputs the adjusted earnings picture that drives every downstream calculation.

Inputs required
  • Client P&L — 3 years preferred
  • Tax returns — 2–3 years
  • Balance sheet
  • Add-backs document — via input template
  • Gary's Excel recast template — defines output format
Output
  • Recast worksheet per year with add-backs itemized
  • Multi-year comparison with % columns
  • QA notes file flagging anomalies for human review
Blocker: Gary's Excel template + source financial statement pending
Agent 02 Built
Observations Agent
Numbers in. Nancy's voice out.
What it does

Reads the recast worksheet output from Agent 01 and writes structured narrative observations in Nancy's voice — fractional CFO tone. Identifies the 3–5 most material findings from the financial picture and explains what they mean for business value in plain language.

Inputs required
  • Recast worksheet — output from Agent 01
  • Industry context — brief description
  • Engagement tier — Express, Explore, Accelerate, or Certified
Output
  • 3–5 structured observations in memo format
  • Each observation: finding, implication, plain-language explanation
  • Data flags section for anomalies Nancy must review
Voice training note

Golden examples from the Fenetex certified report (anonymized) are already populated. This agent knows Nancy's voice — percentages AND dollar figures together, comparative language, confident declarative statements.

Phase 3 — Orchestration Layer

The Agents Work as a Team

This is infrastructure, not more agents. Phase 3 wires the existing agent fleet together so they trigger in sequence from a GHL stage change. A client moving into "Documents Received" fires Agent 01. Agent 01's output fires Agent 02. And so on through the chain. Nancy's involvement shifts from doing the work to reviewing the output at defined checkpoints.

Prerequisite: OS Layer Must Be In Place

Phase 3 orchestration requires the chief-of-staff file, agent registry, handoff spec, and consistent naming convention to all be in place before any sequencing work begins. Without the handoff spec defining exactly what Agent 01 passes to Agent 02, each trigger requires manual routing — which defeats the purpose.

Agent 06 Phase 3
GHL Trigger + Routing Agent
Stage change in. Pipeline initiated.
What it does

Watches for the "Client Documents Received" stage trigger in GHL. Validates that all required documents are present in the client folder. Routes the complete input package to Agent 01 and confirms the handoff. Notifies Nancy if documents are missing before the pipeline fires.

Why this is Phase 3, not Phase 1

This agent has nothing to do until Agents 01–05 are stable and producing reliable output. Building the routing layer before the agents it routes to are proven is backwards.

Agent 07 Phase 3
Report Assembly Agent
All agent outputs in. Complete draft out.
What it does

Collects the outputs from Agents 01, 02, 03, 04, and 05 and assembles them into a single structured report document. Handles ordering, section headers, and formatting consistency. Flags any section where an upstream agent produced a data anomaly that needs Nancy's attention before the draft is finalized.

Output
  • Complete near-final report draft in SBV branded Word template
  • Review checklist noting every flagged section
  • GHL task created: "Nancy — Report Draft Ready for Review"

Phase 4 — Autonomy

Valuations With Minimal Human Initiation

Phase 4 is the long-term end state. As the agent team runs more engagements, Nancy's review patterns — what she edits, what she approves without changes, what she flags — become training data that feeds back into the agents. Over time, the team requires less and less intervention. Nancy's role becomes supervisor, not executor.

Agent 08 Phase 4
Quality Assurance Agent
Draft report in. Audit findings out.
What it does

Runs a structured audit pass on the complete report draft before it reaches Nancy. Checks: internal consistency between narrative and numbers, NACVA standards compliance, missing sections, data flag resolution, and format conformance against the SBV branded template. Returns a scored audit report.

Why Phase 4

This agent requires a large body of completed, approved reports as golden examples before it can audit accurately. It cannot be built until the pipeline has produced enough real output to define what "approved" looks like across engagement types.

Future Phase 4
Feedback Loop
Nancy's edits become the agents' next training.
How compounding works

Every time Nancy edits an agent's output, that edit is captured and categorized. Recurring edits to the same section or same type of observation become updates to the relevant agent's golden examples and context files. The project wrap-up agent (Katie's methodology) closes this loop automatically after each engagement.

The end state this enables

After enough engagements, the agents' output requires progressively fewer edits. Nancy's review time shrinks from hours to minutes. The system is not just faster — it gets better with every report it produces.
